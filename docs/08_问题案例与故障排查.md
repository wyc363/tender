## 2. 故障排查

### API Key缺失
症状：check-only的parser_api_configured或judge_api_configured为false。处理：检查对应env变量名，值使用真实密钥但不得打印；再次check-only。

### ModuleNotFoundError / PYTHONPATH
症状：独立运行测试找不到`md_chunking`、`retrieval`或`r2`。处理：优先用组件入口脚本，它们会设置src路径；测试时把相关`src`加入PYTHONPATH。不要通过复制包解决。

### Docling长时间无输出
当前适配器整本convert结束后才写document.json。检查进程CPU和内存；CPU持续增长表示仍工作。若进程退出，检查pipeline.log和ERROR；若CPU长期不增长再评估停止。大PDF瓶颈主要在OCR。

### VLM invalid JSON
检查raw_responses、request_audit和validation_errors。非法结果不得人工改为SUCCESS；Parser自动使用deterministic fallback。

### Table repair skipped
查看scope、eligible IDs与unrepairable原因。被跳过不等于失败；若source coverage仍100%，属于保守策略。

### Chunk provenance fail
查看Source Coverage、Provenance Validation和Skipped Noncontent Sources。常见原因是旧chunks_raw缓存、空表未登记或heading source未附加。当前orchestrator在上游指纹变化时清理旧Chunk派生产物。

### Top50不足
若可用corpus少于50，Generic Gate要求 `min(50, corpus)`；这不是失败。若corpus大于等于50却不足，检查TOC过滤、candidate重复和检索异常。

### Judge API失败
技术失败必须写technical_error并转REVIEW，不能静默PASS。检查run manifest、raw response、endpoint、模型名、timeout和权限。

### Ungrounded FAIL
模型违规原文无法在anchor/context找到时转REVIEW。检查模型是否改写、是否选错context、相同文本候选和空白归一化。禁止手填页码绕过。

### Resume fingerprint mismatch
表示PDF、Stage代码、配置或关键程序变化。确认变更是否预期；预期则让Stage重跑，不预期则比较manifest哈希。不要编辑manifest伪造恢复。

### 输出目录碰撞
不同PDF不要复用同一手工document ID。推荐省略ID使用SHA派生。发现碰撞时新建唯一ID，不把文件手工覆盖到旧目录。

### DOC011 Gate误用于通用PDF
症状：页数或Chunk数被固定基线拒绝。通用PDF不要传 `--regression-profile DOC011`；只执行Generic Gate。

### 0分/停用模板
模型或召回可能看到模板正文。Judge必须依据“不应用”“0分”“本项目无要求”等实际生效状态；仍不确定时REVIEW。

### 合同阶段与投标阶段混淆
“合同创优”“中标后提交”等不一定作用于投标准入/评分。需结合Rule Scope和章节作用判断，不能仅凭奖项词判FAIL。
