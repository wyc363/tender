# 招标文件智能审查系统

> 文档状态：【当前实现】；工程名：`tender_review_system`；基线日期：2026-09-14。除明确标注【历史探索】【曾用方案】【规划中】【未来工作】外，本文描述当前真实代码与产物。路径采用逻辑根，不绑定开发机器。

逻辑根约定：`<PARSER_ROOT>` 为解析组件，`<CHUNK_ROOT>` 为切分组件，`<RETRIEVAL_ROOT>` 为召回与证据后处理组件，`<JUDGE_ROOT>` 为冻结审查运行组件，`<PIPELINE_ROOT>` 为本地编排组件，`<OUTPUT_ROOT>` 为运行产物根，`<RULE_STORE>` 为规则库，`<FROZEN_PROGRAM>` 为冻结提示程序。

## 推荐阅读顺序

1. `<PIPELINE_ROOT>/review_pipeline/cli.py`：`build_parser()`与`main()`，理解入口参数和输出。
2. `<PIPELINE_ROOT>/config/pipeline.local.yaml`：理解逻辑根、环境和规则路径。

4. `<PIPELINE_ROOT>/review_pipeline/docling_adapter.py`：理解OCR与表格解析配置。
5. `<PARSER_ROOT>/docling_postprocess/page_blocks.py`：`build_page_records()`，理解Source Fact。
6. `<PARSER_ROOT>/docling_postprocess/furniture.py`：`repair()`，理解页眉页脚。
7. `<PARSER_ROOT>/docling_postprocess/deterministic_structure.py`：`heading_decision()`、`build_final_page()`。
8. `<PARSER_ROOT>/docling_postprocess/structure_risk.py`与`table_repair_scope.py`：理解VLM路由边界。
9. `<PARSER_ROOT>/docling_postprocess/vlm_repair_router.py`与`vlm_repair_schema.py`：理解调用和Schema保护。
10. `<PARSER_ROOT>/docling_postprocess/goodmd_renderer.py`：`render_goodmd()`，理解GoodMD/Source Map。
11. `<CHUNK_ROOT>/src/md_chunking/markdown_events.py`：`parse_markdown()`。
12. `<CHUNK_ROOT>/src/md_chunking/chunk_builder.py`：`build_text_region()`、`build_table()`、`build_chunks()`。
13. `<CHUNK_ROOT>/src/md_chunking/chunk_provenance.py`：`enrich_chunks()`。
14. `<RETRIEVAL_ROOT>/src/retrieval/rule_store.py`：`compile_rule_store_config()`。
15. `<RETRIEVAL_ROOT>/src/retrieval/pipeline.py`：`run_retrieval()`。
16. `<JUDGE_ROOT>/src/v03_pilot5/run_frozen_prompt_judge.py`：`load_frozen_prompt()`、`call_model()`、`build_business_output()`。
17. `<RETRIEVAL_ROOT>/run_r2_pipeline.py`：`validate_prediction()`、`deduplicate_findings()`、`postprocess()`。
18. `<RETRIEVAL_ROOT>/src/r2/evidence_mapper.py`：`map_evidence()`与`aggregate_result()`。
19. `<PIPELINE_ROOT>/review_pipeline/gates.py`：Generic与DOC011 Regression Gate。
20. `<PIPELINE_ROOT>/review_pipeline/report.py`：最终合并HTML。
